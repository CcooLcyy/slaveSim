# R2 发布与设备自动更新

## 目标与边界

slaveSim 沿用上位机的 Cloudflare R2 存储桶与参数名称，独立使用 `slavesim` 对象前缀。同时提供 Linux amd64、arm64 的二进制包与 Docker 镜像包。单容器内的常驻管理进程提供网页手动检查与更新，校验后替换模拟器二进制并重启子进程，健康检查失败时回退。

默认不进行自动检查或安装，不安装宿主机服务，不挂载 Docker Socket。更新程序不改动下位机、不重启其他服务、不覆盖现有配置或日志。基础镜像和管理进程升级由管理员单独迁移，参见 [单容器网页更新](单容器网页更新.md)。

## 发布触发与路径

- 基础版本由根目录 `VERSION` 管理，当前为 `0.0.1`。本地普通构建显示基础版本加 `-dev`。
- 推送 `master`：发布 `ci` 通道，版本为 `<基础版本>-ci.<UTC yyyyMMddtHHmmss>+sha.<7 位提交号>`，例如 `0.0.1-ci.20261010t083000+sha.abcdef1`。构建时间在元数据步骤生成一次，两个架构共用；重跑使用新的时间。
- 推送正式版本标签 `vX.Y.Z`：发布 `stable` 通道，版本为 `X.Y.Z`。标签必须来自 `master` 历史且与 `VERSION` 完全一致。正式构建时间使用来源提交时间，保证同标签重跑的构建输入不变。
- 手动运行发布工作流：只用于重新发布当前分支的 `ci`，或指定正式版本标签的 `stable`。
- 同一通道发布串行执行。两种架构的测试、构建都成功后才上传。

对象键与公开地址保持一致：

```text
slavesim/<channel>/latest.json
slavesim/<channel>/<asset-version>/release.json
slavesim/<channel>/<asset-version>/<arch>/slavesim-<asset-version>-linux-<arch>.tar.gz
slavesim/<channel>/<asset-version>/<arch>/slavesim-<asset-version>-linux-<arch>-image.tar.gz
```

`asset-version` 把展示版本中的 `+` 转为 `_`；Docker 镜像同样使用此转换，例如 `slavesim:0.0.1-ci.20261010t083000_sha.abcdef1-arm64`。清单 `version` 与程序显示保留 `+sha.`。

正式版本禁止用不同提交或资产覆盖。先上传、验证全部版本资产，最后上传 `latest.json`。版本资产长期缓存，入口清单禁止缓存。

## 只保留最新版本

每个通道单独保留 `latest.json` 和它指向的一个版本目录。该目录保留 amd64、arm64 各自的二进制包和 Docker 镜像包，以及 `release.json`、`SHA256SUMS`，共六个版本对象；两种压缩包是不同交付形式，并非重复版本。

仅在新版全部资产和公开入口校验成功后，完整分页列出当前通道对象，再逐个删除保留列表以外的对象。删除前确认最新入口未变化、七个保留对象均存在；列表异常、越界或缺失时停止，不执行删除。清理后再次列出对象，确认只剩保留列表。清理失败会让发布任务失败，已经校验成功的新入口仍然有效，重跑可继续清理。

清理仅限配置前缀下的当前通道，不触及另一通道或其他项目。首次采用此规则的成功发布会一并清理旧编号目录。旧版本在线下载地址将失效；设备更新失败时仍使用本机保留的旧镜像和配置回退。

## GitHub 配置

在 `CcooLcyy/slaveSim` 的 Settings → Secrets and variables → Actions 中设置：

| 类型 | 名称 | 说明 |
| --- | --- | --- |
| Secret | `R2_ACCOUNT_ID` | 与上位机同一个 Cloudflare 账户 |
| Secret | `R2_ACCESS_KEY_ID` | 具有目标桶读取、列举、写入和删除对象权限的访问密钥 ID |
| Secret | `R2_SECRET_ACCESS_KEY` | 对应的访问密钥 |
| Variable | `R2_BUCKET` | 默认 `mskdsp-update` |
| Variable | `R2_PREFIX` | 默认 `slavesim`，不得使用上位机的 `mskdsp-upper` 前缀 |
| Variable | `R2_PUBLIC_BASE_URL` | 默认 `https://pub-19f3d71852b04011b120b1b814141c12.r2.dev`，不含对象前缀 |

GitHub 不允许回读已有 Secret 的内容，需要安全地配置到 slaveSim 仓库。凭据只进入发布任务环境，设备只访问公开 HTTPS 下载地址，不需要 R2 写入凭据。

R2 使用 S3 兼容接口和 `auto` region，见 [Cloudflare 官方 AWS CLI 文档](https://developers.cloudflare.com/r2/examples/aws/aws-cli/)。

## 更新清单

清单 `schema_version=1`，包含 `project=slavesim`、`channel`、`version`、`commit`、`published_at` 与 `platforms`。

`platforms` 同时含 `linux-amd64` 与 `linux-arm64`，每项包含：

- `url`、`sha256`、`size`：压缩 Docker 镜像包地址、校验值和字节数。
- `image`、`image_id`：镜像标签与 Docker 配置摘要。
- `binary_url`、`binary_sha256`、`binary_size`：二进制包下载信息。

二进制包包含模拟器、主站探针、示例配置、README 和部署工具；不包含真实 `config.json`、日志或凭据。设备按本机架构选择平台，禁止跨架构安装。

## 网页更新

首次安装基础镜像后，打开 `http://<主机>:16000`。顶部更新卡片显示当前版本、最新版本、通道与更新源，点击“检查更新”，发现新版后点击“更新到最新版”。页面刷新和状态轮询只读取结果，不会自行检查 R2 或安装程序。

管理进程读取只读挂载的 `updater.json` 中 `manifest_url`，选择本机架构的 `binary_url` 包；校验版本、提交、包大小、SHA256 和程序 `-version`。下载期间旧程序继续运行；切换阶段短暂停止并重建 PTY。健康检查通过才提交 `runtime/state.json`；失败恢复本地上一版。`runtime/` 持久保存程序，容器重启仍使用已安装版本。网页更新不改变容器 ID 或镜像。

旧部署首次迁移需要备份原文件、停用旧定时器、复制新版管理工具与 Compose 模板并重建一次容器。完成迁移后不要再用旧的 `update.py` 镜像更新流程；新版脚本在网页模式会明确拒绝旧命令。宿主 `state.json` 是基础镜像安装记录，网页中的当前版本以 `runtime/state.json` 为准。

## 基础镜像安装及旧部署的失败处理

更新程序使用 Linux 文件锁防止重复运行，检查同一版本的提交与镜像身份，拒绝通道错误和版本倒退。下载使用临时文件，严格校验大小和 SHA-256，通过后才 `docker load`，并核对导入镜像的 `image_id`。

新版 CI 按基础版本与 UTC 构建时间排序，SHA 只标识来源；同秒不同身份拒绝覆盖。兼容旧 `0.0.0-ci.<run_number>.<run_attempt>` 清单与安装状态，新编号排在所有旧编号之后，迁移后禁止退回旧编号。版本中的短提交号必须与完整提交一致。

部署使用 `deploy/compose.release.yml` 与独立镜像环境文件。保留配置、日志和软链接目录。只有运行中容器确实属于对应 Compose 项目与部署目录，才允许自动替换；首次部署需要显式授权参数。

成功标准是新镜像容器运行，且 `/api/state` 返回有效总线与 PTY 路径。成功后才提交本地更新状态；失败恢复旧镜像环境并重建旧版本容器，回退失败明确报错。下载、校验或导入失败时不停止当前容器。

更新会重建 PTY，下位机原串口句柄可能短暂失效，需要由下位机自己的重连逻辑恢复。更新程序不会擅自重启下位机。稳定通道适合长期运行；测试通道会随每次 master 推送更新，应按联调需要启用。

## 验收

1. 两架构构建、协议测试与发布工具测试通过。
2. 上传失败不得更新 `latest.json`；清单只能引用已完整上传并验证的资产。
3. 缺少凭据时发布清晰报错，凭据不出现在源码或日志。
4. 下载损坏、架构不符、清单越界、版本冲突时保留当前运行版本。
5. 新版健康检查失败可恢复旧版；回退保留原配置与日志。
6. 并发更新互斥；重复检查同版本不重建容器。
7. 默认不安装设备定时器，操作者明确执行安装命令后才启用。
8. 发布成功后当前通道只有一个版本目录及 `latest.json`；失败不得提前清理，分页、通道边界与两种交付包均经过验证。

## 设备首次安装基础镜像

前提是 Linux、Python 3.9 或以上、Docker 与 Docker Compose v2。准备既有 `config.json`，确保其中所有总线的 `link` 都位于指定的软链接共享目录。若已经运行同名容器，需要操作者先确认并完成迁移；更新器会拒绝直接接管原先 `docker run` 或其他 Compose 目录管理的容器。

以下命令从仓库或已校验并解压的二进制包目录执行。`/home/megsky/serial-sim` 仅为示例，必须与现场配置、下位机容器挂载路径一致。初始化不会覆盖配置，也不会启动容器：

```bash
sudo python3 scripts/update.py init \
  --deploy-dir /opt/slavesim \
  --config /home/megsky/slavesim/config.json \
  --serial-dir /home/megsky/serial-sim \
  --log-dir /home/megsky/slavesim/log \
  --manifest-url https://pub-19f3d71852b04011b120b1b814141c12.r2.dev/slavesim/ci/latest.json

# 先检查，再显式进行首次安装；此步会启动 slaveSim 容器。
sudo python3 /opt/slavesim/update.py check --deploy-dir /opt/slavesim
sudo python3 /opt/slavesim/update.py apply --deploy-dir /opt/slavesim --allow-initial-install

# 首次安装成功后，在网页手动检查和更新。
# http://<设备>:16000
```

旧镜像更新定时器只供尚未迁移的历史部署使用。进入网页模式后，不允许安装该定时器，也不能继续运行旧的 `check`、`apply`；需要先停用既有定时器并替换宿主旧脚本，避免覆盖已更新的程序。管理工具与 Compose 模板固定在部署目录，管理进程固定在基础镜像内，它们的升级由管理员单独迁移。

历史设备仅切换版本编号时，按 [版本编号与迁移](版本编号方案.md) 更新共享版本模块与宿主脚本。迁移到网页更新模式时须同时升级基础镜像、Compose 的 `runtime/` 与 `updater.json` 挂载，保留现场配置、日志和软链接目录，不重新执行 `init`，不恢复旧定时器。

正式环境将清单地址改为 `slavesim/stable/latest.json`。稳定清单只会在首次发布 `vX.Y.Z` 标签后出现。已安装的部署禁止自动跨通道切换，应由操作者明确迁移。

## 本地检查

```bash
python3 -m unittest discover -s test -p 'test_*.py' -v
node --test test/web_update_panel.test.mjs
go vet ./...
go test ./...
```

发布工作流同时运行 Python 工具测试与两架构原生 Go/PTY 测试。当前基础版本对应正式标签 `v0.0.1`，创建标签的行为代表明确发版，不能把 CI 编号当作正式版本。缺少 R2 Secret 时，构建产物仍会保存为 Actions artifact，发布任务明确失败，不会谎报发布成功。
