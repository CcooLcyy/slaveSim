# slaveSim 设计方案

> 状态：**第一期已实施并部署验证通过**。第 9 节验收标准全部达成，实施记录见第 13 节。

## 1. 背景与目标

在没有真实现场设备的情况下，让下位机 `mskdsp` 仍然能跑通"本地串口直连采集与控制"这条链路。

`slaveSim` 通过 PTY 造出虚拟串口设备，扮演 Modbus RTU 从站，让 `mskdsp` 用
`TRANSPORT_SERIAL` + `serial.device=<虚拟串口路径>` 直接连接，从而在实验室里复现现场环境。

对应的下位机侧事实（已核实）：

- `protobuf/ModbusRTU.proto:24-29` 定义 `TRANSPORT_SERIAL = 1`（本地串口直连）与
  `TRANSPORT_MQTT_UART = 2`（经 uartManager 透传）。
- `serial.device` 无默认值，只能由上位机 gRPC 下发后落 SQLite；链路真正 `open()` 时才校验路径。
- 现场点表口径：9600 / 8 / 无校验 / 1 停止位，`device_id = 1..4`，一条 RS485 总线挂多台设备。

## 2. 非目标（第一期不做）

- 不实现 `TRANSPORT_MQTT_UART` / uartManager 透传（模拟环境不安装 uartManager）。
- 不实现 DLT645 从站。
- 不接真实串口硬件。
- 不进入 `MskDSP` 的 CMake 构建与发布链路。
- 不做点表 CSV 导入、tag 关联显示、`follow` 值引擎、帧间隔告警（见第 10 节，后续迭代）。

## 3. 运行环境与部署形态

目标机（x64 模拟服务器，已实测）：

| 项 | 值 |
| --- | --- |
| 主机 | `clsclear.top:32118`，用户 `daniel`（`docker` 组，`sudo` 需交互密码） |
| 系统 | Ubuntu 26.04 / 内核 7.0 / **x86_64** / Docker 29.8.0 |
| 资源 | 12 核 / 60 GB 内存 / 根分区可用约 332 GB |

**模拟器以独立容器运行**（不装宿主机进程、不需要 sudo、用 `--restart unless-stopped` 自启）：

```
slaveSim 容器（普通容器，不需要 --privileged）
  -v /dev/pts:/dev/pts                  # 与 mskdsp 共享 devpts
  -v /home/daniel/serial-sim:/home/daniel/serial-sim    # 存放软链接，两个容器挂同一份、同一路径
  -p 16000:16000                        # WebUI（已实测目标机该端口空闲）
  --restart unless-stopped

mskdsp 容器
  -v /dev/pts:/dev/pts
  -v /home/daniel/serial-sim:/home/daniel/serial-sim
  配置 → transport_type=TRANSPORT_SERIAL, serial.device=/home/daniel/serial-sim/tty0
```

### 3.1 已实测验证的结论

在目标机上用 `mskdsp-lower-runner:ubuntu24.04` 镜像做过完整实验：

| 验证项 | 结果 |
| --- | --- |
| 默认容器能否看到宿主机 `/dev/pts` | ❌ 只有 `ptmx`（独立 devpts 实例） |
| 加 `-v /dev/pts:/dev/pts` 后 | ✅ 宿主机 PTY 全部可见 |
| 容器内 `openpty()` 建的 PTY 是否落到宿主机 | ✅ 宿主机 `/dev/pts` 出现新条目 |
| 另一个容器能否**打开并读取**该 PTY | ✅ 普通非特权容器即可读到数据 |
| 是否需要 `--privileged` / `--device-cgroup-rule` | ❌ 都不需要 |

### 3.2 两个必须遵守的约束

1. **软链接不能建在 `/dev/pts` 里**。devpts 是设备文件系统，放不了普通文件；软链接必须放在
   两个容器共享的普通目录（`/home/daniel/serial-sim`）。
2. **容器都以 root 运行**。PTY 从端属主是创建进程的 uid，用 root 建即 `root:tty`，
   两边权限最简单，不需要处理 uid 映射。

## 4. 总体架构

```
        ┌────────────────────────────────────────┐
WebUI ─▶│  slaveSim                               │
        │  ┌──────────────┐  ┌────────────────┐   │
        │  │ 配置与状态    │  │ 报文日志环形缓冲 │   │
        │  └──────┬───────┘  └───────▲────────┘   │
        │         │                  │            │
        │  ┌──────▼──────────────────┴─────────┐  │
        │  │ 模拟核心                           │  │
        │  │ 总线 → 从站 → 寄存器 + 值引擎       │  │
        │  └──────────────┬────────────────────┘  │
        │                 │ Channel 接口           │
        │                 ▼                        │
        │            PtyChannel（第一期唯一实现）   │
        └─────────────────┬──────────────────────┘
                          ▼
              /dev/pts/N  ←软链←  /home/daniel/serial-sim/tty0
                          ▲
                          │  mskdsp 打开该路径
```

**Channel 抽象**：与下位机 `ModbusRTUBus.h`（`SerialBus` / `MqttBus`）同构。
第一期只实现 `PtyChannel`；后续新增真实串口或 MQTT 通道时，帧编解码与模拟核心完全复用。

## 5. 配置模型

三层：**总线 → 从站 → 寄存器**，对应真实拓扑（一条 RS485 挂多台站号设备）。

```jsonc
{
  "buses": [
    {
      "name": "RS485-1",
      "link": "/home/daniel/serial-sim/tty0",   // 对外暴露的软链接路径
      "slaves": [
        {
          "device_id": 1,
          "response_delay_ms": 0,          // 模拟慢设备
          "unmapped_policy": "exception",  // exception | zero
          "registers": [
            { "function": "0x04", "address": 3004, "type": "INT32",
              "source": { "kind": "const", "value": 100 } },
            { "function": "0x04", "address": 3042, "type": "UINT16",
              "source": { "kind": "sine", "base": 50, "amplitude": 0.2, "period_ms": 60000 } },
            { "function": "0x03", "address": 3069, "type": "UINT16", "access": "readwrite",
              "source": { "kind": "manual", "value": 1 } }
          ]
        }
      ]
    }
  ]
}
```

- **主键是 `function + address`**。模拟器本质是被动响应"功能码 + 地址"，点表 `tag` 是下位机的概念。
- `access`：`readonly`（默认，写它返回异常）/ `readwrite`。
- 配置在 WebUI 中可修改并落盘到 `-v` 挂载的卷内。

### 5.1 数据类型

| type | 寄存器数 | 说明 |
| --- | --- | --- |
| `UINT16` / `INT16` | 1 | 默认 |
| `UINT32` / `INT32` | 2 | 拼接字序由 `word_order` 决定 |
| `BOOL` | 1 | 取 `bit_index` 位（默认 0） |

`word_order`：`HL`（默认）/ `LH`；`byte_order`：`AB`（默认）/ `BA`。
与 `protobuf/ModbusRTU.proto:225-241` 的口径保持一致。

### 5.2 值引擎（第一期）

| kind | 语义 |
| --- | --- |
| `const` | 固定值 |
| `sine` | 以 `base` 为中心、`amplitude` 为幅值、`period_ms` 为周期的正弦 |
| `ramp` | 按 `step`/`period_ms` 线性变化，到边界后按 `wrap` 决定折返或回绕 |
| `random` | 在 `[min, max]` 内随机，按 `period_ms` 刷新 |
| `manual` | 由 WebUI 手动设置，之后保持不变 |

`follow`（写点跟踪，AGC 闭环用）不属于第一期，见第 10 节。

## 6. Modbus RTU 从站行为规范

**总原则：默认行为对齐真实设备**。真机不回包的场景模拟器也绝不能回，否则会掩盖下位机
超时与重试逻辑的缺陷。

### 6.1 不响应（静默丢弃）

| 场景 | 处理 |
| --- | --- |
| 站号不是自己 | 静默丢弃，不响应 |
| CRC16 校验失败 | 静默丢弃，不响应 |
| 帧长度不足 / 结构非法 | 静默丢弃，不响应 |
| 广播地址（`0x00` / `0xFF`） | **执行写操作，但不响应** |

### 6.2 异常响应

| 场景 | 异常码 |
| --- | --- |
| 功能码不支持 | `0x01` 非法功能码 |
| 读/写区间含未配置地址（`unmapped_policy=exception`） | `0x02` 非法数据地址 |
| 写只读寄存器 | `0x02` 非法数据地址 |
| 数量越界（见 6.3） | `0x03` 非法数据值 |
| `0x10` 字节数与数量不匹配 | `0x03` 非法数据值 |

异常帧格式：`站号 + (功能码|0x80) + 异常码 + CRC`。

当 `unmapped_policy=zero` 时，未配置地址返回 0 而不是异常——用于容忍下位机读整段区间。

**跨区间不拼接**：一个读请求如果同时覆盖已配置和未配置地址，整帧返回异常，
不返回"半真半假"的数据。

### 6.3 支持的功能码与数量上限

| 功能码 | 语义 | 数量上限 |
| --- | --- | --- |
| `0x01` | 读线圈 | 1..2000 |
| `0x03` | 读保持寄存器 | 1..125 |
| `0x04` | 读输入寄存器 | 1..125 |
| `0x05` | 写单线圈（`FF00`/`0000`） | — |
| `0x06` | 写单寄存器 | — |
| `0x10` | 写多寄存器 | 1..123 |

### 6.4 串口线设置

**必须对 PTY 从端设置 raw 模式**（`cfmakeraw`）。否则 tty 行规程会回显输入、
转换 CR/LF、并把 `0x03`/`0x11`/`0x13`/`0x1A` 等字节当作控制字符处理，
**直接破坏二进制 Modbus 帧**。

参考现有 C++ 实现 `MskDSP/tools/device-sim/src/main.cc:458-470`：
`openpty()` → `tcgetattr` → `cfmakeraw` → `tcsetattr`。

## 7. WebUI

Go 单二进制 + `//go:embed` 内嵌静态页面，**不引入前端构建链**，浏览器通过 WebSocket 接收实时数据。

页面结构（第一期）：

1. **总线与从站**：查看每条总线对应的实际 `/dev/pts/N`、软链接路径、从站列表与运行状态。
2. **寄存器**：表格编辑每个寄存器的功能码 / 地址 / 类型 / 值来源 / 当前值。
3. **报文日志**：实时滚动显示 `时间戳 / 方向 / 完整十六进制 / 解析结果 / CRC 是否通过`，
   支持暂停与清空。

> 后续迭代会在此加入"工程量与 raw 双列显示"与点表 tag 关联（见第 10 节）。

## 8. 日志

沿用仓库既有格式（中文 + 方向 + 完整十六进制），例如：

```
2026-09-17 15:31:44 [info]  [slaveSim] 报文接收: 总线=RS485-1, 站号=2, 长度=8, 数据=02 03 7D 00 00 01 9C 55
2026-09-17 15:31:44 [info]  [slaveSim] 报文发送: 总线=RS485-1, 站号=2, 长度=7, 数据=02 03 02 00 0A 3D 8E
2026-09-17 15:31:44 [warn]  [slaveSim] CRC 校验失败，已丢弃: 总线=RS485-1, 数据=02 03 7D 00 00 01 00 00
```

## 9. 第一期交付范围

**交付物**

- `slaveSim` Go 源码（单二进制，内嵌 WebUI）
- `Dockerfile`（多阶段构建）+ 部署说明
- 单元测试与集成测试
- 部署到目标机并与 `mskdsp` 端到端验证的记录

**验收标准**

1. 容器启动后，宿主机 `/home/daniel/serial-sim/tty0` 存在且指向有效的 `/dev/pts/N`。
2. `mskdsp` 配 `TRANSPORT_SERIAL` + 该路径后 `StartLink` 成功，轮询能读到配置的点值。
3. 报文日志中收发十六进制完整，CRC 校验通过。
4. 在 WebUI 修改某个寄存器值后，下位机下一轮轮询读到新值。
5. 站号不匹配的请求**不产生响应**（下位机侧表现为超时，与真机一致）。
6. `0x06` 写命令写入的值，能在后续 `0x03` 读中读回。

**测试方案**

- 单元测试（`go test`）：CRC16、帧编解码、请求解析、第 6 节全部异常分支、值引擎。
- 集成测试：进程内建 PTY，用测试用 Modbus 主站客户端打真实帧，校验响应字节。
- 端到端：部署到目标机，与 `mskdsp` 联调，核对第 9 节验收标准。

按优先级：

1. **点表 CSV 导入与 tag 关联显示**：导入 `现场点表/解析结果/modbus_rtu_points.csv`

   算出。界面同时显示两列，用来当场发现量纲错误（现场曾出现 1000 倍量纲错与电流漏 √3 的问题）。

4. **帧间隔违规告警**：锦浪协议要求查询间隔 `>300ms`、控制间隔 `>700ms`，
   模拟器可检测实际到达间隔并告警，同时统计 QPS 与超时率。
5. **DLT645PCD 从站**（若不使用 uartManager，则需要另一条承载通道）。
6. 多总线、真实串口通道、MQTT 通道。

## 13. 实施记录

第一期代码位于本仓库根目录（`main.go` + `internal/`），已构建为 2.72 MB 镜像并部署到目标机运行。

**实测通过的行为**（用自带的主站探针 `cmd/probe` 走真实 PTY 验证）：

| 用例 | 观测结果 |
| --- | --- |
| 站号 1 读 `0x04 @3004` 数量 2 | `01 04 04 00 00 14 D5`，CRC 通过 |
| 站号 9（未配置）读 | 静默超时，无任何响应 |
| 写 `0x06 @40120 = 1234` | 原样回显 |
| 读回 `0x03 @40120` | `01 03 02 04 D2`，值为 1234 |
| 读未配置地址 `0x03 @9999` | `01 83 02`，异常码 `0x02` |
| 不支持的功能码 `0x08` | `01 88 01`，异常码 `0x01` |

### 实施中发现的真实缺陷

**PTY 从端全部关闭时，读取主端返回 `EIO`。** 最初 `readLoop` 遇到错误即 `return`，
导致读写循环永久退出、总线彻底失效。现象很有迷惑性：**第一次请求能通，之后全部超时**，
而且包括本该无条件回异常码的功能码请求也不响应。

修复方式是把它当作暂时状态处理：记录一次告警、短暂休眠后继续循环，等待新的程序重新打开从端。
已补回归测试 `TestBusSurvivesClientDisconnect`（`internal/sim/bus_test.go`），
该测试在没有此修复时必然失败。

另有一个编码缺陷：`byte_order = BA` 最初只在 32 位分支生效，`UINT16`/`INT16` 没有应用字节交换。
已由 `TestByteOrderBA` 覆盖。
