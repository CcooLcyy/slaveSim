# 单容器网页更新

## 目标与边界

一个容器内运行常驻 Python 管理进程和 Go 模拟器子进程。管理进程监听公开 HTTP 端口，普通网页、状态与 SSE 请求代理到仅监听 127.0.0.1 的子进程；更新接口及定时自动更新由管理进程处理。默认每60秒检查并自动安装新版本，网页关闭后仍运行。更新只替换二进制并重启子进程，不替换容器、镜像或管理进程，不挂载 Docker Socket，不安装宿主服务。

现有 updater.json 的 manifest_url 是唯一更新源；网页不得传入 URL、命令或路径。升级基础镜像/管理进程需单独维护。此次首次迁移需要重建一次旧容器，后续网页更新容器 ID 不变。

## 持久化与更新

宿主部署目录新增 runtime/，挂载到 /var/lib/slavesim。保存各版本 slavesim、probe、已安装状态和最近任务结果；保留当前及上一可回滚版本。镜像内 /slavesim、/probe 为首次启动的种子程序。已有持久化状态在容器重启时继续使用，不能覆盖为镜像种子版本。

配置父目录必须可写挂载到 /etc/slavesim，使 Web 保存能够创建同目录临时文件并原子替换；只读或可写的单文件绑定挂载均不能满足原子替换。发布部署保留 updater.json 中的 config_path，由更新器派生 CONFIG_DIR 与 CONFIG_FILENAME，进程读取 /etc/slavesim/${CONFIG_FILENAME}；部署目录的 updater.json 单独只读挂载到 /etc/slavesim/updater.json，不能将现场配置命名为 updater.json。配置目录应供模拟器专用；本地 Compose 使用 conf/ 时还需在其中保存 updater.json，因为目录挂载会遮蔽镜像内的默认更新源。日志保留原挂载，runtime/ 不得在重建容器时丢弃。

管理进程从 updater.json 读取 manifest_url、auto_update（默认true）及check_interval_seconds（默认60秒）；旧的仅含manifest_url配置也采用上述默认自动更新策略，设置auto_update=false并重启管理进程可关闭自动更新。定时任务复用原有串行校验、安装及回滚流程，不并发重复提交；同版本不重启，失败下一轮检查重试。从现有 R2 二进制包获取程序，不导入 Docker 镜像。校验清单项目、通道、版本身份、架构、URL 前缀、包大小、SHA256；归档只允许提取 slavesim 和 probe 两个普通文件，不采用包内配置、脚本、链接或路径。执行候选程序 -version 核对其版本与来源提交。

旧环境启用本机制须先更新一次基础镜像并重建本项目容器，同时保留原配置、日志和runtime/持久化目录。网页二进制更新不会更换Python管理进程，因此不能仅点击网页更新获得此能力。此后的自动安装不负责升级管理进程、基础镜像或宿主脚本；无需恢复旧的宿主Docker镜像定时器。

管理进程启动后等待一个检查间隔才执行首轮，之后按间隔触发；已有任务忙碌时跳过本轮，不排队重试。缺少有效更新源时自动停用；管理进程停止时立即中断调度等待，不再发起新任务。

更新任务串行，重复请求返回 409。下载和校验阶段旧子进程继续服务；校验完成后停止旧子进程、启动候选，检查 /api/state 每条总线有 PTY，再原子提交安装状态。失败启动旧版并校验，明确报告回滚结果。任务中断或容器重启时，以最后已提交状态恢复旧版。启动失败/子进程意外退出要明确报错或有界重启，管理进程退出时终止并回收子进程。

## HTTP 契约与页面

- GET /api/update/status：enabled、current_version、latest_version、source_url、channel、state、message、update_available、job_id，以及auto_update_enabled、check_interval_seconds、next_check_at（UTC ISO8601字符串，无计划时为空）。
- POST /api/update/check：异步检查，202 返回上述状态。
- POST /api/update/apply：异步检查并安装最新版本，202 返回上述状态；同版本不重启。
- state：idle/checking/available/current/updating/succeeded/error；忙时更新按钮禁用。
- POST 要求 X-SlaveSim-Action: update；若有 Origin，则必须和 Host 同源。拒绝跨域、非 POST、非空 JSON 参数和超大请求，不支持用户提供任何运行参数。此机制保护浏览器同源请求，现有部署仍应通过受控内网或 SSH 隧道访问。
- “程序更新”位于“运行工作区”“RS485 配置”之后的独立页签，显示当前/最新版本、来源、结果、自动更新状态、间隔及下次检查时间；手动“检查更新”“更新到最新版”仍可使用。旧服务未返回自动字段时按手动更新显示。切换页签只改变可见性，保留配置草稿；网页加载/轮询只查询状态，不提交自动安装，自动任务独立由管理进程执行。
- 本页发起更新或页面加载时发现正在更新的任务，更新成功后先通过 GET /api/state 确认模拟器恢复，再自动刷新网页加载新版静态资源。后台自动安装即使在两次轮询之间完成，只要本页首次有效状态后实际current_version发生变化并返回成功或当前状态，也确认恢复后刷新。同一页面最多刷新一次；初次读取的历史成功记录、仅latest_version变化、同版本检查或失败回滚不会触发刷新。断线或服务尚未就绪时继续轮询，不重发更新请求。未保存配置仍遵守原有离开页面提醒。

## 验收

先测试清单/包校验、路径穿越、版本冲突、重复操作、成功状态提交、失败回滚和重启恢复，再实现。原 Python 发布/更新及 Go/PTY 测试继续通过。

服务器 /home/daniel/slaveSim 迁移前备份配置、旧 Compose、环境、updater.json、宿主安装状态和已有 runtime/，保留旧 Docker 镜像；停用旧定时器并等待正在执行的任务结束，只重建本项目容器。同时迁移配置目录可写挂载、runtime/ 和只读 updater.json；若基础镜像仍为 scratch，还需单独升级到 Python 管理进程镜像。已有网页部署保留 runtime/ 中的版本，迁移后不再运行宿主镜像更新命令或恢复定时器。具体步骤见 [R2 发布与自动更新](R2发布与自动更新.md)。

验证 R2 检查接口、网页、两站真实 Modbus RTU 响应及 Web 配置保存；以旧版种子启动管理进程，再从 R2 更新到新版本，确认容器 ID 不变、状态新版本与二进制 -version 一致、更新没有覆盖配置、下载临时文件清理；容器重启后仍运行新版本且保存的配置可读取。发生失败恢复旧 Compose、环境、安装状态和镜像。
