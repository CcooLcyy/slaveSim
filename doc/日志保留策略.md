# 日志保留策略

## 目标与边界

保留现有收发报文内容、标准输出与可选文件双写，以及网页 2000 条、后台内存 1000 条上限。文件按大小轮转，不按天删除、不压缩。单个模拟器进程独占一个日志路径，不支持多个进程共享写入。

## 参数与行为

- `-logfile` 为空时仅输出到标准输出；启用文件时，`-log-max-size-mib` 默认 50，必须为正整数，单位 MiB；`-log-backups` 默认 5，必须为非负整数。
- 写入一条日志将超出大小限制时，先轮转，再完整写入该条日志。单条日志超过限制时拒绝文件写入，标准输出保留完整内容。
- 当前文件名不变，历史文件依次为 `.1`、`.2` 等，`.1` 最新；超出保留数量删除最旧文件。保留数量为 0 时，轮转直接清空当前文件。
- 启动时检查已有当前文件；达到或超过大小限制时先轮转。启动时同时清理超出保留数量的本方案历史文件，其他文件不受影响。
- 正常新生成文件的总量最多为 `(历史数量 + 1) × 单文件大小`，默认约 300 MiB。迁移前已有超大文件首次轮转后作为历史保留，可能暂时超预算，后续按正常轮转淘汰；不切割或静默删除已有日志。
- 运行期间写入或轮转失败时保持标准输出，向标准错误报告中文错误，同一进程连续故障最多每分钟提示一次；后续写入尝试恢复。不得在轮转失败后继续无界追加。启动时文件初始化、历史清理或首次轮转失败则明确报错并停止启动，沿用既有文件日志初始化失败的处理方式。
- Python 容器管理进程接收这两个参数，程序更新、回滚及子进程重启后仍使用相同设置。仅透传非默认值，默认值依靠新版 Go 程序内置策略，以兼容回滚到不识别新参数的旧程序；旧程序本身没有文件轮转能力。自定义非默认值时，启动或回滚到不支持参数的旧程序会失败。
- 两份 Compose 明确使用 `json-file` 驱动、`max-size: 10m`、`max-file: "3"`；Docker 标准输出日志约 30 MiB，加文件日志默认约 330 MiB。Compose 变更需要重建容器生效，单独网页更新 Go 程序不会改变 Docker 日志配置或容器管理脚本。

## 验收

- 覆盖正常追加、恰好达到阈值、跨阈值轮转、历史顺序与数量限制、启动时超限、调整保留数、零历史、单条过大和失败后恢复。
- 验证错误提示限频及故障期间标准输出继续输出。
- 验证管理进程参数默认值、校验、子进程透传；检查两份 Compose 日志限额。
- 运行可用的 Go 测试、静态检查及 Python 回归；不修改设备配置或自动重建现场容器。
